# Handover — ansidrama release prep

_Last updated: 2026-07-07. Read this first, then continue from "Next step"._

## What this project is

`ansidrama` — a Rust CLI that turns a terminal session into a crisp animated
**WebP** (`encode` = assemble frames; `record` = drive a command and capture
each frame). Goal of this work: prepare it for a public **MIT-licensed** GitHub
release at **github.com/oetiker/ansidrama** (repo does not exist yet).

The overall effort was decomposed into two sub-projects, each run through the
superpowers flow: **brainstorming → writing-plans → subagent-driven-development
→ finishing-a-development-branch**.

## Sub-project 1 — retire tmux: ✅ DONE, merged to `main`

`record` used to shell out to `tmux`. It now embeds its own terminal in-process
(PTY via `rustix-openpty` + the `vt100` **`deck` fork** as a pinned git dep),
making ansidrama a **zero-runtime-dependency** static binary. New modules:
`src/term.rs`, `src/keys.rs`; `src/record.rs` rewritten; colour resolution in
`src/color.rs`. Native truecolor, tmux-style key names preserved, unix-gated so
`encode` stays portable, smoke test shadows `tmux` on PATH as a regression
guard. Spec/plan: `docs/superpowers/{specs,plans}/2026-07-06-embedded-terminal-*`.
Merged to `main` (merge commit on `main`), all tests green.

### THE ONE REMAINING STEP (only the user can do it)
Run the **Release** workflow on GitHub: Actions → Release → Run workflow →
`release_type = feature`. From the `v0.0.0` baseline that yields **v0.1.0** —
it bumps `Cargo.toml`, rolls `CHANGES.md`, tags `v0.1.0`, builds the 4-target
matrix, and publishes the GitHub Release with tarballs + `.deb` + `.rpm`. This
is the only part never exercised locally. (`gh workflow run release.yml -f
release_type=feature` also works.)

Possible future sub-projects (noted, not started): apt/dnf repo hosted on
GitHub Pages (needs a Pages job + GPG signing); pure-Rust animated-WebP muxer to
drop the libwebp `cc` dependency.

### Decisions locked (with the user)
- **Targets:** Linux `x86_64`+`aarch64` (static **musl**, via `cross`), macOS
  `x86_64`+`aarch64`. `.deb`+`.rpm` for Linux only. No Windows, no dmg/.app, no
  container, no docs site, no crates.io.
- **Packaging:** Rust-native — **`cargo-deb` (3.7.0)** + **`cargo-generate-rpm`
  (0.21.0)**, config in `Cargo.toml` `[package.metadata.deb]` /
  `[package.metadata.generate-rpm]`. (Dropped the earlier nfpm idea — it's a Go
  tool.) Produced inside the two linux-musl build legs via `--no-build --target`.
- **Release flow:** byonk-style `release.yml` — `workflow_dispatch`
  bugfix/feature/major → bump `Cargo.toml` + roll `CHANGES.md` → tag → build
  matrix → GitHub Release. First release **v0.1.0** (run with `feature` from the
  `v0.0.0` baseline). CI mirrors byonk (fmt/clippy/test/build), no tmux install.
- **Docs:** README + hand-written `man/ansidrama.1`. No mdBook site.
- **Demo ("Makes itself"):** `demo/readme.toml` drives interactive `bash`:
  title card → `cat hello.toml` → `ansidrama record hello.toml` (real OK line) →
  `ls -l hello.webp` → "a star is born" card. `hello.toml` drives **`printf`**
  (non-recursive). Output committed at `docs/demo/ansidrama.webp`, regenerated by
  `make demo`. NOTE: `out` in a config is resolved **relative to the config
  dir** — account for that so the file lands at `docs/demo/ansidrama.webp`.
- **WebP:** keep `webp = "0.3"` (libwebp via `cc`) **for now**. Pure-Rust
  animated WebP does NOT exist (`image-webp` does static lossless only; animation
  encode unimplemented) — a pure-Rust ANMF muxer over `image-webp` is a possible
  future sub-project. libwebp under musl is THE build risk (see below).
- **Cargo.toml:** add `repository`/`homepage` = the GitHub URL.

### Build risk to verify FIRST in the plan
The `webp` crate compiles **libwebp via `cc`**. Confirm `cross build --release
--target x86_64-unknown-linux-musl` succeeds before wiring the whole matrix.
Fallback: switch Linux targets to `-gnu` (glibc) — deb/rpm still fine.
